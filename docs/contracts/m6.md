# Email actions and scheduled briefings (M6)

Prepared 25 November 2026. Decisions: [ADR 0601](../adr/0601-email-approval-and-outbox.md) (drafts, approval, outbox, Mailpit), [ADR 0602](../adr/0602-scheduled-briefings.md) (briefings). Schema: [openapi.json](../openapi.json). Earlier contracts are unchanged.

## Tenant configuration

| Vocabulary | Added in M6 |
| --- | --- |
| Pack | `actions` — email drafts from verified reports, approvals, briefings |
| Connector | `mailpit` — development delivery (required to approve and send) |

The NileTech fixture enables both; the isolation tenant enables neither. Existing tenants are not switched on by the migration; an access admin enables them with `PUT /api/v1/admin/tenant/settings`.

## Endpoints (`/api/v1/actions`, bearer session required)

| Method and path | Body | Result |
| --- | --- | --- |
| `GET /recipients` | — | Active users of the caller's tenant `[{user_id, display_name, email}]` |
| `POST /email-drafts` | `{source_run_id, recipient_user_id}` | `201` draft v1 |
| `GET /email-drafts`, `GET /email-drafts/{id}` | — | The caller's drafts |
| `PUT /email-drafts/{id}` | `{version, draft_sha256, recipient_user_id, subject, body}` | New version; approvals invalidated |
| `POST /email-drafts/{id}/approve` | `{version, draft_sha256}` | `{approval_token, action_id, version, draft_sha256, expires_at}` |
| `POST /email-drafts/{id}/send` | `{version, draft_sha256, approval_token}` | `202` draft with `status: queued` and `delivery` |
| `POST /email-drafts/{id}/cancel` | — | Draft `cancelled` (not after the send was claimed) |
| `POST /briefings` | `{question, recipient_user_id, interval_seconds, first_run_at}` | `201` schedule |
| `GET /briefings` | — | Schedules with their last 20 occurrences |
| `POST /briefings/{id}/deactivate` | — | Schedule stopped |

All bodies reject unknown fields. `subject` is one line (≤ 200), `body` ≤ 50 000 characters, `interval_seconds` 3 600–2 678 400, `first_run_at` needs a timezone.

## Draft

```json
{"action_id": "…", "status": "draft", "status_reason": null, "origin": "user",
 "source_run_id": "…", "version": 2, "draft_sha256": "<64 hex>",
 "recipient": {"user_id": "…", "display_name": "…", "email": "…"},
 "subject": "Verified report: …", "body": "…", "content_withheld": false, "edited": true,
 "approval_expires_at": null,
 "delivery": {"execution_key": "…", "message_id": "<…@eaios.local>", "status": "delivered",
              "status_reason": "smtp_accepted", "attempts": 1, "smtp_accepted_at": "…",
              "confirmed_at": "…", "uncertain_since": null, "mailpit_id": null},
 "created_at": "…", "updated_at": "…"}
```

`status`: `draft` → `approved` → `queued` → `sending` → `delivered`, or `uncertain` (the mail server may have accepted it; being reconciled, never re-sent blindly), `blocked` (a check failed at dispatch), `failed`, `cancelled`. `subject`/`body` are `null` with `content_withheld: true` when the viewer can no longer see the source report.

## Errors

| Status, code | When |
| --- | --- |
| `404 not_found` | Unknown, another user's or another tenant's draft, run or schedule |
| `409 version_conflict` | The named version/hash is not the current one |
| `409 approval_rejected` | Forged, foreign, mismatched, other-session, used, superseded or expired approval |
| `409 action_locked` / `too_late` | The draft is no longer editable / the send was already claimed |
| `422 action_blocked` | A current-state check failed: `sender_inactive`, `pack_disabled`, `connector_disabled`, `unsupported_source`, `source_access_revoked`, `source_changed`, `recipient_not_found`, `recipient_inactive`, `recipient_changed`, `recipient_not_authorized` (the reason is in the audit log) |
| `422 unsupported_question` | A briefing question that is not a verified sales report question |
| `422 invalid_request` | Validation, including any extra field |

## Delivery (`email_outbox.status`)

`pending` → `dispatching` → `delivered`; `dispatching` → `pending` (not sent before DATA), `failed` (5xx), `uncertain` (ambiguous after DATA, or claim lease expired); `uncertain` → `delivered` (found in Mailpit) or `pending` (confirmed absent while the receipt-history canary proves Mailpit's history covers the send; otherwise it stays `uncertain` with `receipt_history_unavailable`); `pending`/`dispatching` → `blocked` (re-check failed at claim or at the SMTP handoff) or `pending` → `cancelled`. An expired approval can be replaced by approving the same version again. Settings: `SMTP_HOST`, `SMTP_PORT`, `SMTP_TIMEOUT_SECONDS`, `MAILPIT_API_URL`, `MAIL_FROM`, `MAIL_MESSAGE_ID_DOMAIN`, `ACTION_APPROVAL_TTL_SECONDS`, `EMAIL_DISPATCH_LEASE_SECONDS`, `EMAIL_MAX_ATTEMPTS`, `EMAIL_RECONCILE_ABSENT_CHECKS`.

## Briefing occurrences

`running` → `review` (draft created, `awaiting_human_approval`), `failed` (the run was not published), or `blocked` (`owner_inactive`, `pack_disabled`, `report_pack_disabled`, `recipient_not_authorized`, …).
