# Legal pack, GitHub repositories, code answers and desktop local folders (M5)

Prepared 21 November 2026. Decisions: [ADR 0501](../adr/0501-legal-pack.md) (legal pack), [ADR 0502](../adr/0502-github-repositories-and-code.md) (GitHub and code pack), [ADR 0503](../adr/0503-desktop-local-folder.md) (Electron shell and local folders). Schema: [openapi.json](../openapi.json). Everything else is unchanged from M2–M4 ([reports](reports.md), [documents](documents.md), [admin](admin.md)).

## Tenant configuration

| Vocabulary | Values |
| --- | --- |
| Packs | `documents`, `sales_reports`, `legal`, `code` |
| Connectors | `upload`, `google_drive`, `github`, `local_folder` |
| Run kinds | `report`, `documents`, `legal`, `code` |

The NileTech fixture enables all four packs and connectors; the isolation tenant keeps `documents` and `upload`. As in M4, a disabled pack or connector returns `403 capability_disabled` at the API and stops a run at start and at publication.

## Chat

`POST /api/v1/chat {question, mode}` accepts `mode` = `auto` | `documents` | `report` | `legal` | `code`. `auto` sends contract clause and expiry questions to `legal`, repository code questions to `code`, sales/period questions to `report`, and the rest to `documents`, among enabled packs only.

Which sources each pack searches: `documents` and `legal` — every source except GitHub; `code` — GitHub only.

### Legal answers

Same six events and no-sources template as M3. Each `token` is one sentence, `"<contract title>: <statement>."`, citing one or more passages; a comparison summary sentence cites every compared passage. Each `citation` is an exact code-point span of the cited version (M3 shape). `done.verification`:

```json
{"label": "legal_facts_extracted_and_rechecked", "method": "deterministic_extraction_no_model",
 "quotes": "exact_spans_of_cited_versions", "values": "re_derived_from_cited_quotes",
 "conventions": ["a term of N months starting on day D ends on the day before D + N months",
                 "renewal deadline = expiry minus notice days"],
 "access": "rechecked_at_publication", "model_used": false, "checker": null}
```

Recognised questions: expiry ("When do our contracts expire?", "Which contracts expire in 2027?", "… before 1 January 2027?", a named contract), and clause comparison for termination, liability, payment, confidentiality, governing law, indemnity, warranty, data protection and service levels (named contracts, or all readable contracts that have the clause, at most four).

### Code answers

M3 events and verification. Each `citation` adds:

| Field | Meaning |
| --- | --- |
| `repository`, `path` | `owner/name` and the file path at the cited revision |
| `commit`, `blob_sha` | Commit at which this file version was captured, and its blob |
| `line_start`, `line_end` | 1-based inclusive lines of the quoted span in that file |
| `url` | GitHub permalink to those lines at that commit |

`GET /api/v1/runs/{run}/citations/{cid}` returns the same fields, recomputed from the stored version. `done.verification` adds `lines: "exact_lines_of_the_cited_blob"` and `code_execution: "none"`.

## GitHub sources (admin)

| Route | Needs | Purpose |
| --- | --- | --- |
| `POST /api/v1/admin/sources {kind: "github", name, external_root: "owner/name", external_ref?, department, classification, department_restricted?, allowed_countries?}` | `resource.admin` + `github` connector + the repository in the operator's `allowed_repositories` | Create a repository source (`external_ref` = branch; default: the repository's default branch) |
| `GET /api/v1/admin/sources/{id}` | as M4 | Adds `visibility`, `external_revision` (last verified commit), `unresolved_principals` (collaborators with no linked user) and every path with its state (`active`, `excluded:<reason>`, `unsupported:<reason>`, `too_large:over_10_mb`, `symlink:symlink_not_followed`, `removed`) |
| `POST …/sync`, `GET …/runs/{run}`, `PATCH` | as M4 | Sync stats add `collaborators`, `collaborators_removed`, `unlinked_collaborators`. `status: deleted` tombstones every document of the source |
| `PUT /api/v1/admin/users/{id}/external-accounts {github: "<login>" | null}` | tenant-wide `identity.admin`, not for yourself | Link or unlink a GitHub login; unlinking applies at once |

Sync failure codes: `repository_not_allowed`, `github_not_configured`, `github_auth_failed`, `repository_not_accessible`, `repository_moved`, `collaborators_unavailable`, `ref_not_found`, `tree_truncated`, `github_unavailable`, `content_unavailable`. Any of them denies all of the source's content until a later sync succeeds.

### Operator configuration

`GITHUB_CONNECTOR_CONFIG` names a JSON file readable by the API and the worker (Compose mounts `./var/connectors` at `/run/eaios/connectors`, read-only):

```json
{"tenants": {"niletech": {
  "auth": {"type": "token", "token_file": "/run/eaios/connectors/github-token"},
  "allowed_repositories": ["<owner>/<test-repository>"]}}}
```

Use a fine-grained personal access token restricted to the repository, with repository permissions **Contents: Read-only** and **Metadata: Read-only** (nothing else). Listing collaborators is a Metadata permission, but GitHub also requires the token's *owner* to have write, maintain or admin access to the repository, so create the token from the repository owner's account. The file is re-read on every use. Exact steps: [docs/evidence/m5/OPEN-ITEMS-SETUP.md](../evidence/m5/OPEN-ITEMS-SETUP.md#1-dedicated-private-github-test-repository).

## Desktop local folders

All routes need a session token. The caller owns the folders they register; another user's folder is `404 not_found`.

| Route | Purpose |
| --- | --- |
| `POST /api/v1/local-folders {folder_id, name, device}` | Register (idempotent per `folder_id`). The server assigns owner = caller, department = caller's department, classification `internal`, no restriction, any country. `201` |
| `GET /api/v1/local-folders` | The caller's folders: `shared_groups`, `active_items`, `skipped_items`, `access` |
| `PUT /api/v1/local-folders/{id}/sharing {groups: [key]}` | Replace the groups that may read the folder; only groups the owner belongs to (`422 invalid_group`) |
| `GET /api/v1/local-folders/{id}/items` | Paths the server holds, with state, reason, SHA-256 and last sequence |
| `POST /api/v1/local-folders/{id}/events {events: [...]}` | Up to 50 events, at most 12 MB of content per batch. Returns one result per event, in order |
| `DELETE /api/v1/local-folders/{id}` | Delete the folder source and tombstone every document in it (`204`) |

Event: `{event_id (uuid), seq (per folder, increasing), op: "upsert" | "delete", path (relative, "/"), sha256?, size?, content_base64?}`.

Results: `created`, `updated`, `unchanged` (same SHA-256), `removed`, `noop` (delete of an unknown path), `stale` (sequence not newer than the last applied one for that path; ignored), `duplicate` (event id already applied; `first_result` given), `excluded`, `unsupported` (`file_type`, `checksum_mismatch`, `content_missing`, …), `too_large`, `rejected` (`invalid_path:<traversal|absolute|bad_characters|…>`).

Admins see local folders in `GET /api/v1/admin/sources` (`kind: "local_folder"`, `owner`). They can pause or delete one; attribute changes return `422 managed_by_owner`, and sync requests `422 not_pull_connector`.

## Desktop shell

`apps/desktop` (Electron 39.8.10) loads the web build from `app://eaios` with a strict CSP; the backend must list `app://eaios` in `CORS_ALLOWED_ORIGINS`. The renderer bridge (`window.eaiosDesktop`) offers `setSession`, `chooseFolder`, `addFolder`, `removeFolder`, `listFolders`, `syncNow` and `onStatus`. The web app shows a **Local folders** card only inside the desktop shell and only when the tenant enabled `local_folder`.
