# ADR 0502 — GitHub repositories and the code pack

Status: Accepted for M5 (pending planning review). Relates to: FR-10, FR-02, FR-06, roadmap "GitHub needs repository visibility and revoke/delete handling before Code Agent integration", "Code outputs refer to repository/file revisions and line evidence; version 1 need not execute arbitrary generated code". Implementation: `backend/app/connectors/github.py`, `github_sync.py`, `fencing.py`, `backend/app/code/workflow.py`, migration 0011.

## Decision

1. **A source is one repository and one branch**, bound to one tenant and one owning department. The admin sets department, classification, restriction and countries (layers 1-3, 5). The operator binds each tenant to a server-side read-only token and to the repositories it may sync (`GITHUB_CONNECTOR_CONFIG`, re-read on every use); a tenant admin can only add a listed repository.
2. **Repository-level permissions, verified every run.** Each sync lists every read-capable principal (`GET /repos/{o}/{r}/collaborators?affiliation=all`, which covers outside collaborators, organisation members and teams) and stores them in `github_collaborators` in the final fenced transaction. Layer 4 is derived at authorization time: a login becomes an allow only through a current `external_accounts` link to a tenant user, made by a tenant-wide identity administrator (never for themself). Unlinking applies at the next authorization point; a collaborator removed on GitHub loses access at the next verified sync (≤ 15 minutes in demo mode), as with Drive.
3. **Visibility never widens access.** Visibility (`private`/`internal`/`public`) is recorded each run and a change is audited (`connector.visibility`). A public repository still grants only its linked collaborators.
4. **Fail closed on revocation and deletion.** A deleted source keeps its row; the same repository can be added again as a new source with new documents. 401, 403/404 on the repository (deleted, made private to the token, or access revoked: GitHub does not say which), a rename or transfer (301), a collaborator list the token may not read, or a truncated tree fail the run: `permissions_current` becomes false and all of the source's content is denied at once, and the staleness bound denies it too if the scheduler stops. Files deleted or renamed in the repository are tombstoned (a rename is a delete plus a new path, because Git has no file identity); paths that become excluded are tombstoned too. Deleting the source tombstones every document. The allowlist is checked before any GitHub request.
5. **What is ingested.** Text and code files up to 10 MB (`parsers.VERBATIM_EXTENSIONS`). Hidden files and folders, dependency and build folders, lock files, temporary and minified files are `excluded`; symlinks (mode 120000) are `symlink` (never followed); submodules and other formats are `unsupported`; oversized blobs are `too_large` and never downloaded. Every path gets a `connector_items` row so the admin sees what was skipped and why. Content is downloaded only when the blob SHA changed.
6. **Exact line evidence.** Repository files are parsed verbatim (`parse_code`): only line endings and Unicode normalisation change, and leading blank lines are recorded (`first_line`), so line *n* of the canonical text is a known file line. Chunks are whole lines (`code-lines-v1`). Each version records `source_revision = {repository, ref, commit, path, blob_sha}`, immutably. A code citation names the repository, path, commit, blob and the exact line range of the quoted span, and a GitHub permalink; reopening it re-derives the lines from the stored version.
7. **The code pack.** Run kind `code` searches repository sources only; documents and legal never search them. The M3 verification applies (exact quote of a cited passage, numbers in quotes, development NLI checker, ≤ 2 repairs). Retrieved code is delimited as data. Version 1 never executes code.
8. **Shared fencing.** Claim, lease, fencing token, policy version, redelivery recovery and superseded runs are the Drive implementation (ADR 0401 §9-10), moved into `FencedSyncBase` unchanged.

## Consequences

- A cited commit is the commit at which that file content was captured. An unchanged file keeps its version (and commit) across later syncs; its content is identical at the current head.
- A token without collaborator access (e.g. a read-only token on a repository it does not administer) cannot serve any content. This is deliberate.
- The NLI checker is a natural-language baseline; on code it may reject correct sentences (abstention), which is safe but lowers answer rate. Measured quality on code is M7 work.
