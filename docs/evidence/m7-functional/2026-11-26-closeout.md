## B1: CSP follows the configured API origin

**Change.** `apps/web/nginx.conf` became `nginx.conf.template`. The image build renders it with `apps/web/render-nginx.mjs` from `VITE_API_BASE_URL`, the same build argument the bundle reads. `connect-src` is `'self'` plus exactly that origin. For `localhost`/`127.0.0.1` the other loopback spelling is added too, as before. Anything other than a plain http(s) origin fails the build: a wildcard, another scheme, credentials, a query or fragment, or extra sources. `nginx -t` runs in the image build. The rest of the policy and the server block are unchanged. The workaround `infra/acceptance/nginx.m7.conf` and its mount in `compose.m7.yaml` are removed.

## Backend test container

**Before.** The `backend-tests` image copied only `backend/` to `/app`, so tests that read `../scripts`, `../ml` or `../docs`, or run `git`, failed at collection or with `FileNotFoundError` (36 failures and 2 errors in the PR #18 container run).

**Change.**
- `backend-tests` builds `backend/Dockerfile.test` from the repository root.
- Its context filter, `backend/Dockerfile.test.dockerignore`, is an allowlist: `backend/`, `scripts/`, `ml/` and `docs/`, minus everything git ignores (`var/`, `.env*`, keys, virtualenvs, caches, `dist`, raw GPU output).
- Files sit at `/repo/<tree>` as in a checkout.
- `git` is installed. The checkout's `.git` is mounted read-only at `/repo/.git`, so committed history is read where it lives and is never baked into the image.
- `python3 scripts/dev.py test-backend` is unchanged (`--profile test run --rm --build backend-tests`) and needs no extra mounts. The old `test` stage of `backend/Dockerfile` is removed.

**Checks.**
- **Image contents:** the image's files under `backend scripts ml docs` equal `git ls-files -co --exclude-standard` for those trees: 676 = 676, no difference either way. The ignored 967 MB `ml/parser-benchmark/.venv` is excluded.
- **Private files:** inside the container `/repo/var` and `/repo/.env` do not exist.
- **Git:** `git -C /repo rev-parse HEAD` returns the checkout's HEAD, and writing to `/repo/.git` fails (read-only).
- **First full run, at `3821964`:** 1103 passed, 6 skipped, **1 failed**: `test_m6_actions.py::test_ambiguous_smtp_outcome_is_uncertain_and_never_blindly_retried` (`['unavailable', 'unavailable'] == ['unavailable']`).
  - Cause: a pre-existing test-ordering bug. `test_mailpit_restart_after_acceptance_keeps_the_receipt` queued and crashed a delivery before checking `TEST_MAILPIT_RESTART_CMD`. Where that command is absent (this container) it skipped and left a stale `dispatching` row, which the next test's reconciliation found. CI sets the command, which hid it.
  - Fix (`59195cb`): check the precondition before creating state. That test still skips in the container, because restarting Mailpit from inside would need the Docker socket. With the fix, `test_m6_actions.py` gives 37 passed, 1 skipped.
  - Also fixed: `/repo/backend` was root-owned (created by `WORKDIR`), so pytest could not write its cache.
