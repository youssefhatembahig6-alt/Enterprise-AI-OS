## B1: CSP follows the configured API origin

**Change.** `apps/web/nginx.conf` became `nginx.conf.template`. The image build renders it with `apps/web/render-nginx.mjs` from `VITE_API_BASE_URL`, the same build argument the bundle reads. `connect-src` is `'self'` plus exactly that origin. For `localhost`/`127.0.0.1` the other loopback spelling is added too, as before. Anything other than a plain http(s) origin fails the build: a wildcard, another scheme, credentials, a query or fragment, or extra sources. `nginx -t` runs in the image build. The rest of the policy and the server block are unchanged. The workaround `infra/acceptance/nginx.m7.conf` and its mount in `compose.m7.yaml` are removed.

## Backend test container

**Before.** The `backend-tests` image copied only `backend/` to `/app`, so tests that read `../scripts`, `../ml` or `../docs`, or run `git`, failed at collection or with `FileNotFoundError` (36 failures and 2 errors in the PR #18 container run).

**Change (current design, after the PR #19 review; see [Review revision](#review-revision-pr-19)).**
- `python3 scripts/dev.py test-backend` (and `python3 scripts/m7_acceptance.py test-backend`, pinned to the disposable project) first runs `scripts/test_context.py`. It stages a fresh temporary context containing:
  - only the **git-indexed** files of `backend/`, `scripts/`, `ml/` and `docs/`, with their working-tree contents. Untracked and ignored files (`var/`, `.env*`, keys, virtualenvs, raw GPU output) never enter.
  - **no human-label submissions**, even when tracked: files in the fixtures' `pilot/labels/` directory other than its README are dropped.
  - a **one-commit git snapshot** of exactly those files. No object, ref or config comes from the checkout's `.git`; nothing is mounted.
  - a manifest, `.eaios-test-context`. `backend/Dockerfile.test` copies it first, so building from an unstaged directory fails.
- Compose builds `backend-tests` from that context (`EAIOS_TEST_CONTEXT`), lays the files out at `/repo/<tree>` as in a checkout, and installs `git`. The temporary context is deleted afterwards. The old `test` stage of `backend/Dockerfile` is removed.
- The tests need no real history: they create their own temporary repositories. The unit suite passes in an image with no repository at all.

*First version (superseded by the review):* an allowlist `.dockerignore` over the checkout, plus the shared `.git` mounted read-only. The reviewer pointed out that the mount exposed private refs (the local labels commit) and that untracked files under the allowlisted trees would enter the context.

**Checks (first version, at `3821964`).**
- **First full run, at `3821964`:** 1103 passed, 6 skipped, **1 failed**: `test_m6_actions.py::test_ambiguous_smtp_outcome_is_uncertain_and_never_blindly_retried` (`['unavailable', 'unavailable'] == ['unavailable']`).

Where that command is absent (this container) it skipped and left a stale `dispatching` row, which the next test's reconciliation found. CI sets the command, which hid it.
  - Fix (`59195cb`): check the precondition before creating state. That test still skips in the container, because restarting Mailpit from inside would need the Docker socket. With the fix, `test_m6_actions.py` gives 37 passed, 1 skipped.
  - Also fixed: `/repo/backend` was root-owned (created by `WORKDIR`), so pytest could not write its cache.

### Finding 1: private labels and local artifacts out of the test build and runtime

The staged context replaces the `.dockerignore` and the `.git` mount (design above).

**Isolation, end to end.** Run on a throwaway `git clone --no-local --single-branch` of this branch, and on a linked worktree of that clone (`.git` is a gitfile). Both were seeded with synthetic sentinels:
- a **tracked** label file committed on the branch;
- an **untracked** label file;
- `var/m7-labels/gold.csv` and `backend/.env`;
- a file inside `ml/parser-benchmark/.venv/`;
- an untracked doc, and an untracked file outside the four trees;
- a **synthetic private ref** `refs/private/m7-labels`, pointing at a commit that is on no branch and holds a label blob.

The worktree also had an uncommitted edit to a tracked file. For each one: stage, build the image from the stage, inspect, run the unit suite in the image (`--network none`). Scans used `/usr/bin/grep`. The interactive shell's `grep` wrapper honours `.gitignore` and had hidden 3 of the 7 planted files in a first control run.

### Finding 2: strict API base URL

`apps/web/render-nginx.mjs` now validates the raw text before parsing; the WHATWG parser silently repairs `http:host` and drops an empty `?`/`#`. Only `http://` or `https://` followed by a host (DNS name, IPv4 or bracketed IPv6), an optional port 1–65535 and an optional path of unreserved characters is accepted. The parsed URL must agree with the raw text. Each rejection names its reason. The loopback alias is a `Map` of exactly `localhost` and `127.0.0.1`. Before the fix, an object lookup gave `http://constructor:8000` an extra source, `http://function Object() { [native code] }:8000`.
